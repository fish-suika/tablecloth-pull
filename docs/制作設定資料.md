# テーブルクロス引き（仮） — 制作設定資料（2026-10-25）

## 決定事項

**本人が決めたこと**
- 題材はテーブルクロス引き。操作は画面スワイプ（ゲーム案ノート）
- スコアは連続で何回成功したか（ゲーム案ノート）
- 実際のテーブルクロス引きより大袈裟な表現を入れる（ゲーム案ノート）
- 他の遊びと組み合わせるかどうかは、遊んでから決める。組み合わせるときも、分かりやすさ・すぐ理解できることを優先する（ゲーム案ノート）
- 成功と失敗を決める軸は **「ちょうどいい速さ」**：遅いと物が引きずられ、速すぎると勢いで物が跳ねる。物ごとにちょうどいい速さが違う（2026-10-25 選択）
- 見た目は **3D・斜め上から**。ブラウザ（three.js）（2026-10-25 選択）
- 大袈裟な表現は **載る物がエスカレートしていく** 形で出す。連続成功が増えるほど、物がばかばかしくなり、演出も派手になる（2026-10-25 選択）

**Claude 案（既定値どおり・異論がなければこのまま）**
- スマホ縦画面基準（PC・横持ちもレスポンシブ）、結果画面に控えめな X 共有ボタン
- 1回失敗したら終了（連続成功数がスコアなので）。自己ベストを保存する
- 結果は指を離した瞬間に決める。揺れて待たせるのは「ギリギリ」のときだけ（テンポの課題への対応。5. を参照）

## 0. 面白さの分析（分解・考察・再構築）

学習メモ「企画・ゲーム設計」の方法で分析した（2026-10-25）。

**分解：本物のテーブルクロス引きの面白さ**
1. 常識と逆になる気持ちよさ：そっと引くと失敗し、思い切り引くと成功する。迷ったら負けの度胸試し
2. 一瞬で結果が出る：引くのは一瞬。そのあと物が揺れて「残るか？」と緊張し、残れば一気にほっとする
3. 失敗しても面白い：ひっくり返るのも見ていて楽しい。成功にも失敗にも見せ場がある
4. 載っている物で緊張が変わる：高いグラスやケーキだと、失敗したときの損が大きく見える

**考察：ゲームにすると何が問題か**
- 「速いほど成功」だけだと全力スワイプが正解になり単調 → 判断の余地が要る。本人の選択で「ちょうどいい速さ」にした。スワイプの速さを狙った通りに出すこと自体が腕前になり、物の組み合わせを見て速さを決める読みも生まれる
- 揺れを待つ時間でテンポが落ちる → 結果は指を離した瞬間に決める。ギリギリのときだけ待たせると、待ち時間が退屈ではなく緊張になる
- 学習メモ（10/25）「誇張でも褒める」「ノーリアクションをなくす」：成功・失敗どちらにも大きな反応を返す

**再構築**
- 核は **1回のスワイプで「ちょうどいい速さ」を出す度胸と手加減の勝負**
- 大袈裟さと「もう1回」の気持ちは、**載る物のエスカレート** で出す。他の遊びと組み合わせなくても独自性が出て、ひと目で分かる

## 1. ゲーム概要

- タイトル：テーブルクロス引き（仮）
- ジャンル・視点：1スワイプのタイミング系アクション／3D・斜め上から見下ろす
- コンセプト：**ちょうどいい速さでクロスを引き抜け。載る物はどんどんおかしくなる**
- 目指す楽しさ：思った速さで引けた手応え／ギリギリで残ったときのほっとする感じ／次に何が載るのかの期待／失敗したときの派手な崩れ方
- 基本の体験：テーブルが出てくる → 載っている物を見て速さを決める → 下へスワイプ → 一瞬で結果 → 次のテーブル

## 2. ゲーム内容

**プレイヤーの役割**：クロス引きの名人（見えない手。画面には手やキャラは出さなくてよい）

**基本操作**
- テーブルクロスの手前の垂れた部分（画面下側）に指を置き、手前（画面の下）へスワイプして引く
- 速さは指を離すまでのスワイプの速さで測る（測り方の細部は Claude が調整）
- 一定の距離を引かずに指を離したら、引いていない扱い（やり直せる）

**基本ルール**
- 物にはそれぞれ「ちょうどいい速さの幅」がある
  - 遅すぎる → 物がクロスに引きずられて倒れる・落ちる
  - 速すぎる → 勢いで物が跳ね上がって倒れる（実物より大袈裟に、高く飛ぶ）
- テーブルに複数の物が載っていると、全部の幅が重なる範囲だけが成功になる（物が増えるほど狭くなる）
- 物の性格は見た目から読めるようにする（例：重い鉄鍋＝速めでないと引きずる、軽い紙コップ＝速すぎると飛ぶ、背の高いグラス＝幅が狭い）。重い物と軽い物が一緒に載ると「真ん中くらい」を狙う読みになる
- 1回でも失敗したら終了。スコアは連続成功数

**ゲームの流れ**
1. タイトル（自己ベスト表示）→ タップで開始。前置きは短く、最初のテーブルからすぐ遊べる（学習メモ 10/13）
2. テーブルが滑り込んでくる → スワイプ → 結果 → 次のテーブルが滑り込む（1テーブルあたり約2秒を目安）
3. 失敗 → 派手に崩れる → 結果画面（連続成功数・自己ベスト・もう一回・X 共有）

**攻略・工夫の要素**
- 物の組み合わせから速さを読む
- 自分のスワイプの速さを狙って調整する手加減
- 引いた後に速さメーター（どこに当たったか、成功の幅はどこか）を一瞬見せる。次の読みの材料になる

**エスカレート（Claude 案。中身は遊びながら調整）**

| 連続成功 | 載る物の例 | 難しさ |
|---|---|---|
| 1〜3 | コップ、皿（1つ） | 幅が広い。操作に慣れる |
| 4〜7 | 食器が2〜3個、ろうそく | 重い物と軽い物の組み合わせが出る |
| 8〜12 | シャンパンタワー、ウェディングケーキ | 幅が狭くなる |
| 13〜19 | 金魚の水槽、高そうな花瓶、トランプタワー | さらに狭い |
| 20〜 | 寝ている猫、王様の冠、雪だるま… | ばかばかしさ優先。ランダムに出す |

**必要な演出・フィードバック**（ノーリアクションをなくす・誇張して褒める）
- 引いた瞬間：クロスがムチのようにしなって画面外へ飛んでいく、風切り音
- 成功：物が一瞬ふわっと浮いて着地、歓声、「お見事！」などの褒め言葉、連続数のカウンターが弾む。連続数が増えるほど歓声や演出が大きくなる
- ギリギリ成功：スローになって物がぐらぐら揺れ、残った瞬間に大きく褒める（「神業！」など）
- 失敗（遅い）：物がずるずる引きずられて床へ落ち、割れる
- 失敗（速い）：物がロケットのように高く跳ね上がり、落ちてきて派手に割れる
- 失敗は笑える崩れ方にする（悔しさより「もう一回」）

## 3. 制作方針

- 使用環境・技術：ブラウザ（HTML＋JavaScript、three.js r128 を CDN から）。既存の 3D ブラウザ作品（ゼリースルーなど）と同じ `src/` 分割＋`sh build.sh` で1枚の HTML に結合
- 素材・制約：見た目は three.js の基本形状（箱・円柱・球など）を組み合わせて作る。効果音は Web Audio で合成（必要なら後で Audio Studio）
- 見た目の方向性：明るくておかしみのある見た目。レストランやパーティー会場の舞台のようなテーブル、白いクロス、スポットライト。物はデフォルメした形でかわいく
- 操作・カメラ：カメラはテーブルの手前・斜め上から固定。クロスの垂れた部分が画面下側に来て、下へスワイプする向きが自然になる配置。演出時だけ揺れ・寄り・スローを入れる
- 優先順位：遊べる状態 → 「ちょうどいい速さ」が面白いかの確認 → エスカレートと演出 → 見た目

## 4. 技術的な実現方法（Claude）

- **物理エンジンは使わず、判定は数値で、動きは演出用のアニメーションで作る。** 指を離した瞬間に速さと成功の幅を比べて結果を決め、その結果に合うアニメーション（着地・揺れ・引きずり・跳ね上げ）を再生する。物理エンジンで本当に計算すると、結果が出るまで待つ時間が長く、ばらつきで理不尽にもなるため（テンポの課題への対応）
- 速さ：画面の高さに対する割合で正規化した「スワイプ距離 ÷ 時間」。画面サイズや PC・スマホの差が出にくいようにする。調整値は `src/10-config.js` の `CFG`
- 判定ロジック（速さ・物の幅・重なり・ギリギリ判定・エスカレートの選び方）は three.js から切り離し、`verify.html` で検証できるようにする
- 自己ベストは localStorage（使えないときは保存しないだけで遊べる）
- X 共有：スマホは Web Share API（結果画面の画像付き）、PC は X の投稿画面（文章＋URL）
- 画面の文章は文節の途中で改行しない

## 5. 仕様上の問題と対応案（Claude・実装前の報告）

| 問題 | 対応案 |
|---|---|
| 揺れを待つ時間でテンポが落ちる（ゲーム案ノートの課題） | 結果は指を離した瞬間に決める。成功時の揺れは短く（0.3秒程度）、ギリギリのときだけスローで長く揺らす。失敗演出も1秒程度で結果画面へ |
| 「ちょうどいい速さ」がプレイヤーに分からないと理不尽になる | 物の見た目で性格を読めるようにする＋引いた後に速さメーターで「どこに当たったか」を毎回見せる。最初の数テーブルは幅を広くして感覚をつかませる |
| 速さを測る方法で、PC のマウスとスマホの指で差が出る | 画面の高さで正規化する。PC とスマホで実際に試して、必要なら係数を分ける |
| スワイプ前から成功の幅を見せるかどうか | 見せると「狙った速さを出す腕前」だけの勝負、見せないと「読み」も入る。Phase 1 では切り替えられるようにして、遊んで決める |
| 物理演算を使わないと、崩れ方が単調に見えるおそれ | 失敗パターン（引きずり・跳ね上げ）ごとに、物の種類に応じた動きを数種類用意してランダムに混ぜる |
| 他の遊びと組み合わせるか | 本人の方針どおり、Phase 1・2 を遊んでから決める。組み合わせる場合は分かりやすさを優先し、この資料に追記する |

## 6. 完成条件

共通：起動できる／スワイプで引ける／判定と連続成功のスコアが機能する／失敗して結果画面まで進める／致命的なバグがない。

この作品の条件：
- **ちょうどいい速さを狙う手応え**がある（遅すぎ・速すぎの両方で失敗し、狙って成功できる）
- **テンポが落ちない**（1テーブル約2秒、待たされる感じがない）
- **載る物のエスカレート**が少なくとも20連続まで用意されていて、次に何が出るか楽しみになる
- 成功・ギリギリ・失敗（遅い／速い）それぞれに **大袈裟な反応** がある
- スマホ縦画面で遊べて、PC でも遊べる。結果画面から X に共有できる

## 7. 実装計画

- **Phase 1：核の最小版**
  3D のテーブルとクロス、物1種類。下へスワイプで引く → 速さを測る → 成功・遅い・速いの3通りの判定と簡単なアニメーション → 次のテーブル。連続成功数の表示と速さメーター。成功の幅の事前表示は切り替えられるようにする。判定ロジックの `verify.html`
  → **ここで本人が遊ぶ**（「ちょうどいい速さ」が面白いか、組み合わせが要るか）
- **Phase 2：物の種類と組み合わせ**
  物を5〜6種類（性格が見た目で分かる）。複数の物で幅が重なる判定。エスカレート表の前半（〜12連続）。ギリギリ判定とスロー演出
- **Phase 3：大袈裟な演出**
  クロスのしなり、物の浮き・跳ね上げ・割れ、歓声・褒め言葉、カメラの揺れ。効果音
  → **ここで本人が遊ぶ**（通しで遊べる版）
- **Phase 4：エスカレート後半と仕上げ**
  20連続以降のばかばかしい物、タイトル・結果画面、自己ベスト、X 共有、レスポンシブ確認
- **最終チェック → まとめて修正（1回まで）**
